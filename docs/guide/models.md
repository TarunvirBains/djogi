# Models

A Djogi model is a plain Rust struct annotated with `#[derive(Model)]` and `#[model(...)]`. The proc macro injects the three framework fields, generates all CRUD methods, and registers the model with the migration differ. You define only the business fields.

This document is a complete reference for every `#[model(...)]` attribute, every `#[field(...)]` attribute, and every field type Djogi supports.

---

## Anatomy of a Model

```rust
use djogi::prelude::*;

#[derive(Model, Debug, Clone, Serialize, Deserialize)]
#[model(table = "articles")]
pub struct Article {
    pub title: String,
    pub slug: String,
    pub body: String,
    pub published: bool,
}
```

After macro expansion, the struct gains three injected fields that are real struct fields backed by real database columns:

```rust
// Effective struct after expansion — do not write this by hand
pub struct Article {
    pub id: HeerId,                       // BIGINT PRIMARY KEY DEFAULT generate_id()
    pub created_at: time::OffsetDateTime, // TIMESTAMPTZ NOT NULL DEFAULT now()
    pub updated_at: time::OffsetDateTime, // TIMESTAMPTZ NOT NULL DEFAULT now()

    pub title: String,
    pub slug: String,
    pub body: String,
    pub published: bool,
}
```

The macro also generates:

| Generated item | Purpose |
|---|---|
| `impl Model for Article` | `objects()`, `get()`, `create()`, `save()`, `delete()`, `descriptor()` |
| `impl FromRow for Article` | SQLx row deserialization |
| `ArticleFields` | Typed field accessors for filter closures |
| `ArticleFilter` | Programmatic filter builder for shell and dynamic use |
| `Article::descriptor()` | `ModelDescriptor` — submitted via `inventory` for app registration and migration differ |

## Model Attributes (`#[model(...)]`)

### `table = "name"` — required

The Postgres table name. Must be provided on every model.

```rust
#[model(table = "articles")]
pub struct Article { ... }
```

Table names are the developer's choice — Djogi performs no automatic pluralization or case transformation. Use the name that matches your database schema or domain conventions.

---

### `pk = "heerid"` | `"ranjid"` | `"serial"` — default: `"heerid"`

Controls the primary key type and generation strategy.

**`"heerid"` (default):** 64-bit `BIGINT`, time-ordered, generated by `generate_id()` at the database level.

```rust
#[model(table = "posts", pk = "heerid")]  // identical to omitting pk entirely
pub struct Post { ... }
```

Generated SQL:
```sql
id BIGINT PRIMARY KEY DEFAULT generate_id()
```

`HeerId` always serializes as a `String` in JSON — JavaScript cannot represent 64-bit integers without precision loss.

**`"ranjid"`:** 128-bit UUIDv8-compatible identifier for applications that outgrow HeerId's capacity. Sub-millisecond precision, up to 32,767 nodes, 65,535 IDs per node per timestamp unit.

```rust
#[model(table = "high_volume_events", pk = "ranjid")]
pub struct Event {
    pub kind: String,
    pub payload: Jsonb<EventPayload>,
}
```

Generated SQL:
```sql
id UUID PRIMARY KEY DEFAULT generate_ranj_id()
```

Use `"ranjid"` when:
- You anticipate more than 8,192 inserts per millisecond per node, or
- You need more than 512 distinct node IDs, or
- You want UUID-compatible storage for interoperability with existing tooling.

HeerId is losslessly upgradeable to RanjId — you can migrate a table from HeerId to RanjId without data loss when you need more headroom.

**`"serial"`:** Standard Postgres `SERIAL` (auto-incrementing `INTEGER`). Suitable for small reference tables where human-readable sequential IDs are genuinely useful.

```rust
#[model(table = "fuel_types", pk = "serial")]
pub struct FuelType {
    pub name: String,
    pub code: String,
}
```

Generated SQL:
```sql
id SERIAL PRIMARY KEY
```

Do not use `"serial"` for application data tables. Its sequential, predictable nature makes it unsuitable as a public-facing identifier.

---

### `partition_by = "range:column"` | `"hash:column:N"`

Declares the table as a Postgres partitioned table. Djogi generates the `PARTITION BY` clause in the `CREATE TABLE` migration and includes partition-key requirements in query warnings.

**Range partitioning** — used for time-series or date-bucketed data:

```rust
#[model(table = "events", partition_by = "range:occurred_at")]
pub struct Event {
    pub occurred_at: time::OffsetDateTime,
    pub kind: String,
    pub payload: Jsonb<EventPayload>,
}
```

Generated SQL:
```sql
CREATE TABLE events (
    id           BIGINT PRIMARY KEY DEFAULT generate_id(),
    occurred_at  TIMESTAMPTZ NOT NULL,
    kind         TEXT NOT NULL,
    payload      JSONB NOT NULL,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT now()
) PARTITION BY RANGE (occurred_at);
```

**Hash partitioning** — distributes rows evenly across N partitions by hash of the partition key:

```rust
#[model(table = "user_events", partition_by = "hash:user_id:8")]
pub struct UserEvent {
    pub user_id: ForeignKey<User>,
    pub kind: String,
}
```

Generated SQL:
```sql
CREATE TABLE user_events (
    id       BIGINT PRIMARY KEY DEFAULT generate_id(),
    user_id  BIGINT NOT NULL,
    kind     TEXT NOT NULL,
    ...
) PARTITION BY HASH (user_id);
```

> **Warning:** Queries against partitioned tables that do not include the partition key in the `WHERE` clause result in full partition scans. Djogi emits a compile-time warning when it detects a `QuerySet` filter on a partitioned table that does not constrain the partition key. Use `cargo djogi analyze` to get a table health report.

### `idempotency_key = "field_name"`

Designates a field as an idempotency key, enabling the `create_or_find()` method. The named field must be a unique column (Djogi adds the `UNIQUE` constraint automatically).

```rust
#[model(table = "payments", idempotency_key = "external_ref")]
pub struct Payment {
    pub external_ref: String,   // UNIQUE — used as idempotency key
    pub amount_cents: i64,
    pub currency: String,
    pub status: String,
}
```

This generates:

```rust
// Returns the existing record if external_ref already exists, or creates a new one.
// Equivalent to: INSERT ... ON CONFLICT (external_ref) DO NOTHING RETURNING *
// followed by SELECT ... WHERE external_ref = $1 if nothing was inserted.
Payment::create_or_find(pool, Payment {
    external_ref: "pay_ABC123".into(),
    amount_cents: 9900,
    currency: "USD".into(),
    status: "pending".into(),
    ..Default::default()
}).await?;
```

Use `create_or_find()` for webhook receivers, payment processors, or any external system that may deliver the same event more than once.

---

### `events`

Enables the transactional outbox pattern for this model. When set, every `create()`, `save()`, and `delete()` call can publish events atomically within the same database transaction.

```rust
#[model(table = "orders", events)]
pub struct Order {
    pub customer_id: ForeignKey<Customer>,
    pub total_cents: i64,
    pub status: String,
}
```

With `events` enabled, the model gains:

```rust
// Create the record and publish an event in the same transaction
let mut tx = pool.begin().await?;
let order = Order::create_in_tx(&mut tx, Order {
    customer_id: customer.id.into(),
    total_cents: 4999,
    status: "pending".into(),
    ..Default::default()
}).await?;
order.publish_event(&mut tx, "order.created", &order).await?;
tx.commit().await?;
// Both the INSERT and the outbox row commit together — or neither does.
```

The outbox table (`_djogi_outbox`) is created automatically. A background worker (provided by `djogi::outbox::Worker`) polls this table and delivers events to the configured sink (Kafka, NATS, HTTP webhook, etc.).

---

### `tenant_key = "field_name"`

Enables Row Level Security (RLS) isolation for multi-tenant models. The named field becomes the tenant discriminator, and Djogi generates the RLS policy SQL.

```rust
#[model(table = "invoices", tenant_key = "org_id")]
pub struct Invoice {
    pub org_id: HeerId,       // must be present as an explicit field — not a ForeignKey
    pub number: String,
    pub total_cents: i64,
    pub status: String,
}
```

See the [Security guide](./security.md) for complete RLS documentation including `djogi::set_tenant()`, `TenantScoped<T>`, and `_insecurely()` methods.

---

### `rationale = "..."`

An advisory documentation string. Does not affect generated code. Surfaced by `cargo djogi docs` and in the admin panel — provides context for AI coding agents, new team members, and schema reviewers.

```rust
#[model(
    table = "audit_entries",
    rationale = "Append-only audit log. Records must never be updated or deleted. \
                 Retention policy: 7 years for compliance. Write via audit::record() only."
)]
pub struct AuditEntry {
    pub actor_id: HeerId,
    pub action: String,
    pub target_table: String,
    pub target_id: HeerId,
    pub payload: Jsonb<AuditPayload>,
}
```

> **Note for AI coding agents:** When a model has a `rationale`, read it before writing any code that touches the model. The rationale captures constraints and intentions that are not expressible in the type system.

---

### `cache_ttl = N`

Opt-in Redis cache TTL in seconds. When set, `get()` and `fetch_one()` results are cached and invalidated on `save()` or `delete()`. Requires the `cache` feature flag and a Redis connection configured in `Djogi.toml`.

```rust
#[model(table = "country_codes", pk = "serial", cache_ttl = 3600)]
pub struct CountryCode {
    pub iso_alpha2: String,
    pub name: String,
}
```

Use `cache_ttl` only for data that changes rarely and is read frequently — small reference tables, configuration rows, and similar. Never use it for user-mutable application data where stale reads are harmful.

---

### `dirty_tracking`

Enables per-field dirty tracking for this model (per-model override of the global `dirty_tracking` setting in `Djogi.toml`). When enabled, `save()` issues `UPDATE` only for fields that changed since the record was fetched.

```rust
#[model(table = "user_profiles", dirty_tracking)]
pub struct UserProfile {
    pub display_name: String,
    pub bio: Option<String>,
    pub avatar_url: Option<String>,
}
```

```rust
let mut profile = UserProfile::get(&pool, id).await?;
profile.bio = Some("Updated bio".into());
// Emits: UPDATE user_profiles SET bio = $1, updated_at = $2 WHERE id = $3
// display_name and avatar_url are NOT included in the UPDATE.
profile.save(&pool).await?;
```

Without dirty tracking, `save()` always issues a full-row `UPDATE` for all fields.

---

### `crud_log = true` | `crud_log = false`

Opts a model in or out of CRUD audit logging, overriding the global `[features].crud_log` setting. See the [logging spec](../spec/logging.md) for the full audit architecture.

```rust
#[model(table = "vehicles", crud_log = true)]
pub struct Vehicle { ... }

// Opt out even when crud_log is globally enabled
#[model(table = "internal_tokens", crud_log = false)]
pub struct InternalToken { ... }
```

## Field Attributes (`#[field(...)]`)

Field attributes go on individual struct fields and refine how the proc macro generates the column definition and query accessors.

### `#[field(lazy)]`

Marks the field as lazy-loaded. Lazy fields are excluded from `SELECT *` and from the default `FromRow` deserialization path. They are loaded only when explicitly requested via `.load()`.

```rust
#[derive(Model)]
#[model(table = "posts")]
pub struct Post {
    pub title: String,
    pub slug: String,
    #[field(lazy)]
    pub body: String,         // TEXT column — not loaded in Post::objects().fetch_all()
}
```

```rust
// body is not populated here — it is the zero value (empty String)
let posts = Post::objects().fetch_all(&pool).await?;

// Load body for a specific post — one extra query
let body = posts[0].body.load(&pool).await?;
println!("{}", body);
```

Use `#[field(lazy)]` for large text or binary columns that are expensive to transfer and not needed in list views. Do not use it for columns that are needed in nearly every access pattern — the extra query cost adds up.

---

### `#[field(outbox = "ignore")]`

Excludes a field from the transactional outbox event payload. Use for secrets, internal tokens, or data that must not leave the database perimeter.

```rust
#[derive(Model)]
#[model(table = "users", events)]
pub struct User {
    pub email: String,
    #[field(outbox = "ignore")]
    pub password_hash: String,  // excluded from outbox events — never emitted externally
    pub display_name: String,
}
```

---

### `#[field(rationale = "...")]`

An advisory documentation string on a field. Surfaced by `cargo djogi docs` and in the admin panel.

```rust
#[field(rationale = "Stripe customer ID — set once on first payment, never updated. \
                     Null means the user has never purchased.")]
pub stripe_customer_id: Option<String>,
```

---

### `#[field(shadow_of = "old_column")]`

Dual-write support during online schema migrations. When a field is annotated with `shadow_of`, every `save()` writes the new field value and also writes the same value to the old column. This allows a zero-downtime rename: deploy the new field, backfill, verify, then remove the old column in a follow-up migration.

```rust
#[derive(Model)]
#[model(table = "users")]
pub struct User {
    pub username: String,           // old column — being phased out
    #[field(shadow_of = "username")]
    pub handle: String,             // new column — writes to both handle and username
}
```

Remove `shadow_of` once the old column is confirmed unused and before dropping it.

---

### `#[field(renamed_from = "old_name")]`

Informs the migration differ that this field was renamed from an existing column rather than being newly added. Without this annotation, the differ would generate a `DROP COLUMN old_name` + `ADD COLUMN new_name` pair, destroying data.

```rust
#[derive(Model)]
#[model(table = "vehicles")]
pub struct Vehicle {
    pub make: String,
    #[field(renamed_from = "model")]   // was: pub model: String
    pub model_name: String,
}
```

Generated migration SQL:
```sql
-- With renamed_from: safe rename, no data loss
ALTER TABLE vehicles RENAME COLUMN model TO model_name;
```

Without `renamed_from`:
```sql
-- Without annotation: data destruction
ALTER TABLE vehicles DROP COLUMN model;   -- data gone
ALTER TABLE vehicles ADD COLUMN model_name TEXT NOT NULL DEFAULT '';
```

Always annotate renames with `renamed_from`. Remove the annotation after the migration has been applied to all environments.

---

### `#[field(unique)]`

Adds a `UNIQUE` constraint on the column.

```rust
pub struct User {
    #[field(unique)]
    pub email: String,
    #[field(unique)]
    pub username: String,
}
```

---

### `#[field(index)]`

Creates a B-tree index on the column.

```rust
pub struct Post {
    #[field(index)]
    pub slug: String,
    #[field(index)]
    pub published_at: Option<time::OffsetDateTime>,
}
```

---

### `#[field(on_delete = "cascade")]` | `"restrict"` | `"set_null"` | `"set_default"`

Sets the `ON DELETE` behavior for `ForeignKey<T>` fields. The default is `RESTRICT` — Postgres will refuse to delete a referenced row if child rows exist.

```rust
pub struct Comment {
    #[field(on_delete = "cascade")]    // delete comments when the post is deleted
    pub post_id: ForeignKey<Post>,

    pub author_id: ForeignKey<User>,   // default: RESTRICT — cannot delete a user with comments
}
```

> **Warning:** `cascade` means data is silently deleted when the parent record is removed. Use it deliberately. `RESTRICT` (the default) forces the developer to explicitly clean up related records, making the dependency visible.

---

### `#[field(max_length = N)]`

Emits a `CHECK (length(column) <= N)` constraint. This enforces the length at the database level independent of application validation. Use `VarChar<N>` as the field type instead if you also want compile-time length enforcement.

```rust
pub struct Tag {
    #[field(max_length = 50)]
    pub name: String,
}
```

## Field Types

### Scalar Types

| Rust type | Postgres type | Notes |
|---|---|---|
| `String` | `TEXT NOT NULL` | UTF-8, unbounded length |
| `VarChar<N>` | `VARCHAR(N) NOT NULL` | Compile-time max length; validated at construction and decode |
| `i32` | `INTEGER NOT NULL` | 32-bit signed integer |
| `i64` | `BIGINT NOT NULL` | 64-bit signed integer |
| `f64` | `DOUBLE PRECISION NOT NULL` | IEEE 754 double |
| `bool` | `BOOLEAN NOT NULL` | `true` / `false` |
| `rust_decimal::Decimal` | `NUMERIC NOT NULL` | Exact decimal arithmetic; use for monetary values |
| `time::OffsetDateTime` | `TIMESTAMPTZ NOT NULL` | Timezone-aware timestamp |
| `time::Date` | `DATE NOT NULL` | Calendar date without time |
| `Vec<u8>` | `BYTEA NOT NULL` | Raw binary |
| `uuid::Uuid` | `UUID NOT NULL` | UUID — used by RanjId and for interoperability |

### Nullable Types

Wrap any type in `Option<T>` to produce a nullable column:

```rust
pub struct Profile {
    pub display_name: String,          // TEXT NOT NULL
    pub bio: Option<String>,           // TEXT (nullable)
    pub avatar_url: Option<String>,    // TEXT (nullable)
    pub birth_date: Option<time::Date>, // DATE (nullable)
}
```

### `VarChar<N>`

`VarChar<N>` is a `String` with a compile-time maximum byte length. Construction via `VarChar::new()` returns `Result` — the value is validated before it can be stored. Decoding from a database row also validates the length and returns an error if the stored value exceeds N.

```rust
use djogi::types::VarChar;

#[derive(Model)]
#[model(table = "tags")]
pub struct Tag {
    pub name: VarChar<100>,    // VARCHAR(100) NOT NULL — enforced at construction and decode
    pub slug: VarChar<100>,
}

// Construction
let name = VarChar::<100>::new("Rust")?;              // Ok
let bad  = VarChar::<100>::new(&"x".repeat(101))?;   // Err: exceeds 100 bytes
```

Use `VarChar<N>` when the length limit is load-bearing — API surface contracts, database index efficiency, or UI display constraints. Use `String` when the limit is advisory or enforced at the application layer.

### `Lazy<T>`

`Lazy<T>` is the type used for `#[field(lazy)]` fields. It holds either a loaded value or a sentinel indicating the field was not fetched. Accessing `.load()` issues one additional query to fetch the field value from the database.

```rust
#[derive(Model)]
#[model(table = "articles")]
pub struct Article {
    pub title: String,
    #[field(lazy)]
    pub body: Lazy<String>,    // TEXT — loaded only on demand
}

// body is not fetched in list queries
let articles = Article::objects().fetch_all(&pool).await?;

// Explicitly load the body for one article
let body: String = articles[0].body.load(&pool).await?;
```

`Lazy<T>` cannot be used in filter closures — lazy fields are not available until explicitly loaded.

### `ForeignKey<T>`

`ForeignKey<T>` stores the `id` of a related model as a `BIGINT` column with a foreign key constraint. The related record is not loaded automatically — you must call `.fetch()` or use `.prefetch()` on the `QuerySet`.

```rust
#[derive(Model)]
#[model(table = "comments")]
pub struct Comment {
    #[field(on_delete = "cascade")]
    pub post_id: ForeignKey<Post>,     // BIGINT REFERENCES posts(id) ON DELETE CASCADE
    pub author_id: ForeignKey<User>,   // BIGINT REFERENCES users(id) ON DELETE RESTRICT
    pub body: String,
}

// Single fetch — one additional query
let post = comment.post_id.fetch(&pool).await?;

// Prefetch on QuerySet — one IN(...) query per relation, not N+1
let comments = Comment::objects()
    .prefetch(CommentRelated::post())
    .prefetch(CommentRelated::author())
    .fetch_all(&pool).await?;

// After prefetch, resolved() is free — no additional query
let post = comments[0].post_id.resolved();  // -> Option<&Post>
```

For a `ForeignKey<T>` field named `post_id`, the generated column is `post_id BIGINT NOT NULL REFERENCES posts(id)`. The suffix `_id` is convention — the column stores only the referenced ID.

### `Jsonb<T>`

`Jsonb<T>` is a JSONB column with a typed Rust schema. The field validates its data before any write. Unknown fields (present in the database but absent from the schema) are preserved across every `save()`.

```rust
use djogi::prelude::*;

#[derive(JsonSchema, Serialize, Deserialize, Validate)]
pub struct EngineSpec {
    pub cylinders: i32,
    #[validate(range(min = 0, max = 2000))]
    pub horsepower: i32,
    pub turbo: Option<bool>,
}

#[derive(Model)]
#[model(table = "vehicles")]
pub struct Vehicle {
    pub make: String,
    pub engine: Jsonb<EngineSpec>,   // JSONB NOT NULL
}
```

See the [JSONB Schema Fields spec](../spec/jsonb.md) for the full `Jsonb<T>` API including unknown field access, nested schemas, subfield query filters, and validation error paths.

### `serde_json::Value`

For untyped, schema-less JSONB. Use when the structure is genuinely dynamic and cannot be modeled with a schema type.

```rust
pub struct Webhook {
    pub source: String,
    pub raw_payload: serde_json::Value,   // JSONB NOT NULL — untyped
}
```

`serde_json::Value` fields have no compile-time validation and no unknown-field preservation. Prefer `Jsonb<T>` for any data that has a known structure.

## Many-to-Many Relationships

Implicit M2M fields are not provided by Djogi. All M2M relationships require an explicit through model. This avoids the forced migration that implicit join tables eventually require when you need to store data on the relationship.

```rust
#[derive(Model)]
#[model(table = "person_groups", through)]
pub struct PersonGroup {
    pub person_id: ForeignKey<Person>,
    pub group_id: ForeignKey<Group>,
    pub joined_at: time::OffsetDateTime,
    pub role: String,
}

// Declare the relationship in both directions — method name comes from RELATION, not auto-pluralized
impl ManyToMany<Group> for Person {
    type Through = PersonGroup;
    const RELATION: &'static str = "groups";   // generates person.groups()
}

impl ManyToMany<Person> for Group {
    type Through = PersonGroup;
    const RELATION: &'static str = "members";  // generates group.members()
}
```

Generated convenience methods:

```rust
// Person side
let groups = person.groups(&pool).await?;
person.add_to_group(&pool, &group, PersonGroup {
    role: "admin".into(),
    ..Default::default()
}).await?;
person.remove_from_group(&pool, &group).await?;

// Group side
let members = group.members(&pool).await?;

// Through model is a full Model — directly queryable
let admins = PersonGroup::objects()
    .filter(|f| f.role.eq("admin"))
    .fetch_all(&pool).await?;
```

## Dirty Tracking

When enabled (globally via `Djogi.toml` or per-model via `#[model(dirty_tracking)]`), `save()` issues `UPDATE` only for fields that changed since the record was last loaded from the database.

```rust
let mut car = Vehicle::get(&pool, id).await?;
car.gas_fill = 80;
// Emits: UPDATE vehicles SET gas_fill = $1, updated_at = $2 WHERE id = $3
// All other fields are omitted from the UPDATE.
car.save(&pool).await?;
```

Without dirty tracking, `save()` always performs a full-row UPDATE. Dirty tracking is off by default — enable it when UPDATE query size is a genuine performance concern or when partial-update auditing is needed.
