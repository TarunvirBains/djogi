# Projections (Transport-Safe Views)

Phase 4.5 generates audience-specific Rust types from every `#[model]`
so backend route handlers stop leaking raw persistence structs into
API payloads, shared contracts, and frontend code. Field exposure is
**opt-in**: fields without a `#[field(expose(...))]` annotation do not
appear in any transport projection.

## The four generated types

For every `#[model]` struct `Foo`, the macro emits:

| Type         | Audience                              |
|--------------|---------------------------------------|
| `FooPublic`  | Unauthenticated API consumers         |
| `FooSelfView`| The owning user                       |
| `FooAdmin`   | Admin users / back-office tools       |
| `FooExport`  | CSV / data-export pipelines           |

Each carries framework columns (`id`, `created_at`, `updated_at`) by
default and derives `Debug`, `Clone`, `Serialize`, `Deserialize`
unconditionally.

The `Foo` struct itself IS the internal form. No `FooInternal` is
generated — `expose(internal)` is accepted as a documentation-only
sentinel with the same semantics as the absent case.

## Minimum boilerplate

```rust
use djogi::prelude::*;

#[model(table = "users")]
#[derive(Debug, Clone)]
pub struct User {
    #[field(expose(public, self_view, admin, export))]
    pub display_name: String,

    #[field(expose(self_view, admin, export))]
    pub email: String,

    // No annotation = `internal`. Never appears in any transport
    // projection. Safe default — data leaks require an explicit opt-in.
    pub password_hash: String,
}
```

Generates:

```rust
pub struct UserPublic {
    pub id: HeerId,
    pub created_at: DateTime,
    pub updated_at: DateTime,
    pub display_name: String,
}

pub struct UserSelfView {
    pub id: HeerId,
    pub created_at: DateTime,
    pub updated_at: DateTime,
    pub display_name: String,
    pub email: String,
}

// UserAdmin and UserExport: same shape as UserSelfView.
```

`password_hash` appears in none of the four projections — omitting the
annotation is the safe default.

## Converting a model to a projection

Scalar-only projections (no relation-form entries) get an infallible
`impl From<&Model>`:

```rust
let user: User = /* ... load from DB ... */;
let public: UserPublic = UserPublic::from(&user);
axum::Json(public) // send to a public API consumer
```

Relation-nesting projections (at least one `expose(scope = "Peer")`
on a relation field) get a fallible `impl TryFrom<&Model>`:

```rust
let vehicle: Vehicle = vehicle_qs.prefetch(|r| r.owner()).fetch_one(&mut ctx).await?;
let public: VehiclePublic = VehiclePublic::try_from(&vehicle)?;
```

If the relation wasn't prefetched / selected, `try_from` returns
`ProjectionError::UnresolvedRelation { model, field, scope }`. The
fix: call `.prefetch()` or `.select_related()` on the queryset before
projecting.

## Scalar form vs relation form

**Scalar form** — bare scope name. The field appears under its
column name in each listed scope:

```rust
#[field(expose(public, admin))]
pub display_name: String,
```

**Relation form** — key-value syntax. The field is a relation
(`ForeignKey<T>` / `OneToOneField<T>`) and is projected as a named
peer projection in each listed scope:

```rust
#[field(expose(public = "OwnerPublic", admin = "OwnerAdmin"))]
pub owner: ForeignKey<Owner>,
```

The peer name must be a type already in scope — typically another
projection generated by Djogi on the target model (`OwnerPublic`
here), or a hand-written DTO.

**Mixing is compile-rejected** on the same scope:

```rust
#[field(expose(public, public = "X"))]   // ERROR — scope `public` declared twice
```

But different scopes can use different forms on the same field:

```rust
#[field(expose(public, admin = "OwnerDetail"))]
pub owner: ForeignKey<Owner>,
```

(Though most models stick to one form per field for readability.)

## Default exposure is `internal`

A field without `#[field(expose(...))]` does NOT appear in any
transport projection. This is intentional: adding a field to a model
should never silently leak it into a public API on the next `git
pull`. Exposing is always explicit.

Sentinels for clarity:

```rust
#[field(expose(none))]       // explicit "not exposed anywhere"
#[field(expose(internal))]   // same as `none`, documents intent
```

Both are equivalent to omitting the annotation. They exist only so
code reviewers can see at a glance that the author considered and
declined to expose the field.

## Framework columns are always exposed

`id`, `created_at`, `updated_at` appear in every generated projection
with no annotation required. Transport contracts nearly always need
these, and requiring an explicit opt-in would be hostile to the
common case. If you need to hide framework columns from a specific
scope, file an issue — a later phase will add `#[model(expose_framework
= "...")]` when the need is concrete.

## ProjectionError

Relation-nesting `TryFrom` paths return this error:

```rust
#[non_exhaustive]
pub enum ProjectionError {
    UnresolvedRelation {
        model: &'static str,
        field: &'static str,
        scope: &'static str,
    },
}
```

The variant fires when a relation field's `.resolved()` returns
`None` — i.e. the caller didn't prefetch / select_related the
relation. The `#[non_exhaustive]` attribute means you must write `_ =>
...` when matching: later phases (e.g. Phase 7.5 protected-data) may
add variants.

Handler-level recovery pattern:

```rust
async fn get_vehicle(id: HeerId, mut ctx: DjogiContext) -> Result<Json<VehiclePublic>, AppError> {
    let vehicle = Vehicle::filter()
        .id_eq(id)
        .prefetch(|r| r.owner())   // <-- the fix site
        .fetch_one(&mut ctx)
        .await?;
    let public = VehiclePublic::try_from(&vehicle)?;
    Ok(Json(public))
}
```

## Shared-contract crate pattern

Projections carry no `djogi` runtime bound — they are pure data +
serde. A common workspace layout for sharing contracts between
backend and a Rust frontend:

```
myapp/
├── myapp_models/      ← defines #[model] structs. Depends on djogi.
├── myapp_backend/     ← HTTP + DB. Depends on myapp_models + djogi.
└── myapp_frontend/    ← e.g. Leptos/Dioxus. Depends on myapp_models ONLY.
```

The frontend crate imports `FooPublic` / `FooSelfView` without
pulling in `djogi` (or `sqlx`, or `tokio`) — the projections are just
structs the macro emitted in `myapp_models`.

## Common compile errors

Seven compile-fail cases are pinned by trybuild fixtures:

| Annotation                                                | Error                                                                 |
|-----------------------------------------------------------|-----------------------------------------------------------------------|
| `#[field(expose())]`                                      | `\`expose(...)\` requires at least one scope`                         |
| `#[field(expose(notascope))]`                             | `unknown scope \`notascope\`; expected one of: public, self_view, ...`|
| `#[field(expose(public, public = "X"))]`                  | `scope \`public\` already declared as bare scope`                     |
| `#[field(expose(none, public))]`                          | `\`none\` / \`internal\` cannot be combined with other scopes`        |
| `#[field(expose(public = "X"))]` on a `String`            | `the \`expose(public = "...")\` form is only valid on relation fields`|
| `#[field(expose(public))]` on a `ForeignKey<T>`           | `relation fields require an explicit peer projection name`            |
| `#[field(expose(public = "X"))]` on `Option<ForeignKey<T>>` | `Option<ForeignKey<T>> ... is deferred to a follow-up phase`        |

All errors carry span-precise locations. Fix the annotation and the
error goes away.

## What's deferred

Phase 4.5 intentionally does NOT ship:

- **Custom user-defined scopes** — only the four built-ins. Deferred
  until at least one app needs a fifth scope.
- **Field renaming** — no `#[field(expose(public = "display_name as
  name"))]` rename syntax. Rename at the serde level if you need a
  different JSON shape.
- **`Option<ForeignKey<T>>` in relation-form** — requires cross-model
  dispatch for `Option<&T>` → peer projection, deferred. Use a
  required FK in Phase 4.5 or stitch optional relations by hand.
- **Many-to-many projections** — projections nest only through
  `ForeignKey<T>` / `OneToOneField<T>`. M2M stitching is manual.
- **JSONB subfield projection** — per-subfield masking of `Jsonb<T>`
  fields is deferred.
- **Protected-data / `#[field(sensitive)]`** — Phase 7.5.
- **Admin UI / export UI** consuming projection metadata — Phase 9.

All of the above are non-breaking additions when they land — the
Phase 4.5 grammar is a strict subset of the larger grammar those
phases will enable.
